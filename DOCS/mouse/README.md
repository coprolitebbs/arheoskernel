# Драйвер мыши PS/2 (i8042 AUX)

Драйвер указательных устройств IBM PC/AT (AUX-порт контроллера i8042, IRQ12).
Разделение обязанностей сделано так:

- **ядро** (`isr.c`) — читает порты контроллера: обработчики
  IRQ1 и IRQ12 вычитывают выходной буфер i8042, раскладывают байты по биту
  AUX и копят мышиные байты в ядерном кольце - это сделано по той причине, что, если передоверять чтение порта напрямую драйверу, он начинает терять и съедать байты от клавиатуры PS/2 на том же порту; 
- **драйвер** (`mouse.drv`) — детект мыши (handshake при загрузке, пока
  прерывания замаскированы), разбор пакетов из ядерного кольца, реестр
  провайдеров и единый курсор (модель Windows: несколько устройств двигают
  один курсор, их дельты суммируются, кнопки объединяются по OR).

Исходники: `drivers/mouse/` (`mouse.c`, `mouse_start.asm`), ABI —
`drivers/include_drivers/drv_format.h` (`MOUSE_ABI_VERSION 2`).

| Файл | Роль |
|---|---|
| `drivers/mouse/mouse.c` | детект PS/2, poll-провайдер, реестр провайдеров, единый курсор |
| `drivers/mouse/mouse_start.asm` | заголовок DRV1 и точка входа |
| `drivers/include_drivers/drv_format.h` | `mouse_driver_api_t`, `mouse_state_t`, коды `MPST_*` |
| `isr.c`, `isr.h` | кольцо AUX-байтов, `kernel_mouse_read_byte`, `kernel_i8042_drain` |
| `use_drivers.c` | загрузка из `/adrv/`, пришивка указателей ядра, маскирование IRQ |
| `task.c`, `syscalls.c` | poll из планировщика, системные вызовы `SYS_MOUSE_*` |

## Схема работы

```
   PS/2 мышь (пакеты по 3 байта, 40 отчетов/с)
        │  IRQ12 (int 44)      скан-коды клавиатуры идут параллельно: IRQ1 (int 33)
        v
   ┌──────────────────── ЯДРО (isr.c) ─────────────────────┐
   │  irq44_handler / irq33_handler:                       │
   │    kernel_i8042_drain():                              │
   │      вычитывает 0x64/0x60 (до 16 байт) и раскладывает │
   │      AUX=1 → кольцо mouse_rx[128] (SPSC)              │
   │      AUX=0 → kbd_hotkey_process + irq_callback        │
   │  EOI в PIC2 и PIC1                                    │
   └──────────────────────┬────────────────────────────────┘
                          │  api->read_byte = kernel_mouse_read_byte
                          v
   ┌──────────────── mouse.c (mouse.drv) ──────────────────┐
   │  mouse_ps2_poll():                                    │
   │    сборка 3-байтовых пакетов (bit3 — синхронизация)   │
   │    знаковые дельты (9-битное дополнение), dy инверсия │
   │    ps2_acc_dx/dy += ..., кнопки = bits 0..2           │
   │  mouse_api_poll():                                    │
   │    сумма дельт всех провайдеров, кламп к экрану,      │
   │    cur_buttons = OR кнопок всех провайдеров           │
   └──────────────────────┬────────────────────────────────┘
                          │  poll() вызывают: schedule() каждый тик таймера,
                          │  SYS_MOUSE_GET (72) и SYS_MOUSE_POLL (73)
                          v
   ┌──────────────── Пользователь (Ring 3) ────────────────┐
   │  userspace/lib/mouse.c: u_mouse_get / u_mouse_poll /  │
   │  u_mouse_set_pos; пример userspace/examples/mouse_test│
   │  Курсор рисует само приложение через фреймбуфер,      │
   │  ядро позицию только хранит                           │
   └───────────────────────────────────────────────────────┘
```

## Аппаратные порты

```
I8042_STATUS   0x64    // статус: bit0 OBF (есть байт), bit1 IBF (ввод занят),
                       //         bit5 AUX (байт в буфере — от мыши)
I8042_DATA     0x60    // данные: скан-коды, байты мыши, конфигурация контроллера
```

Контроллер выдает байты мыши и скан-коды клавиатуры через один выходной
буфер — различить их можно только по биту AUX статуса. Именно поэтому порт
опрашивается ядром, а не драйвером. Команды мыши идут только через префикс
0xD4 (запись в 0x64: следующий байт в 0x60 уйдет в AUX-порт). Перед каждой
записью драйвер ждет сброса бита IBF. Таймауты заданы в итерациях опроса:
`TIMEOUT_FAST 200000` (ожидание ACK), `TIMEOUT_RESET 1000000` (ожидание 0xAA
после Reset), `TIMEOUT_CCB 200000` — реальное железо отвечает десятки
миллисекунд, эмуляторы мгновенно.

## Детект PS/2 (mouse_ps2_init)

Диалог методом опроса (polled) с контроллером и мышью. На время детекта
клавиатурный порт отключается командой 0xAD, чтобы пользователь, печатающий
в момент загрузки, не вклинил клавиатурный байт в диалог.

1. `0xAD` — отключить клавиатурный порт, слить мусор из выходного буфера
   (хвосты BAT-теста BIOS).
2. `0xA7`/`0xA8` — выключить и включить AUX-порт: приводит контроллер в
   заведомое состояние (на 86Box без этого AUX иногда спит).
3. `0x20` — прочитать байт конфигурации контроллера (CCB): выставить bit1
   (разрешить IRQ12 от AUX), сбросить bit5 (разрешить тактирование AUX),
   записать обратно командой `0x60` через порт данных.
4. `0xFF` — Reset: ACK 0xFA, затем 0xAA (самотест) и id устройства 0x00.
   Блок шагов 4–6 делается дважды: часть контроллеров теряет первый Reset,
   если между 0xA8 и командой прошло слишком мало времени (наблюдалось на
   86Box).
5. `0xF6` — заводские настройки по умолчанию.
6. `0xF3 0x28` — частота опроса 40 отчетов/с.
7. `0xF4` — разрешить стриминг отчетов.

Выход из любого шага: слить остатки буфера и вернуть клавиатуру командой
0xAE — раньше при неудаче после шага 1 ядро оставалось без клавиатуры до
перезагрузки. Если мышь найдена, провайдер регистрируется в реестре
(`"ps2"`, тип `PTYPE_PS2`, приоритет 10).

## Коды шага детекта (MPST_*)

Если мышь не нашлась, драйвер записывает в `debug4` шаг, на котором
остановилась инициализация, в `debug5` — последний принятый байт. Ядро
(`use_drivers.c`) печатает расшифровку на загрузочном экране — сразу видно,
настройка ли это эмулятора или проблема кода:

| Код | Шаг | Сообщение |
|---|---|---|
| `MPST_WR_TIMEOUT` | контроллер не принимает байт (IBF не снимается) | `no mouse (i8042 write timeout)` |
| `MPST_NO_CCB` | нет ответа на чтение CCB (0x20) | `no mouse (i8042 not responding)` |
| `MPST_NO_ACK` | мышь не ответила ACK на Reset 0xFF | `no mouse (no ACK to reset...)` |
| `MPST_NO_BT` | после Reset нет 0xAA (самотест провалился) | `no mouse (no 0xAA after reset, got XX)` |
| `MPST_NO_F6` | нет ACK на 0xF6 (defaults) | `no mouse (0xF6 defaults no ACK)` |
| `MPST_NO_F3` | нет ACK на 0xF3 (частота) или параметр | `no mouse (0xF3 rate no ACK)` |
| `MPST_NO_F4` | нет ACK на 0xF4 (enable reporting) | `no mouse (0xF4 enable no ACK)` |

## Обработка прерываний (ядерная часть)

Оба обработчика — `irq33_handler` (IRQ1) и `irq44_handler` (IRQ12) — вызывают
общий тракт `kernel_i8042_drain()` и только потом шлют EOI. Drain читает
статус 0x64 и, пока взведен бит OBF, забирает байты из 0x60 (ограничение
16 итераций, вызов из ISR):

- **AUX=1** — байт мыши кладется в кольцо `mouse_rx[128]` (SPSC: head пишет
  только ISR, tail — только читатель; вложений нет, общий стаб isr.asm не
  включает IF). При переполнении байт отбрасывается со счетчиком — граница
  пакета развалится, драйвер пересинхронизируется по бит3 первого байта.
- **AUX=0** — скан-код: сначала `kbd_hotkey_process` (горячие клавиши
  раскладки), затем `kbd_driver_api->irq_callback`.

Драйвер забирает байты функцией `kernel_mouse_read_byte(uint8_t *out)`
(0 — байт получен, -1 — кольцо пусто). Флаг `mouse_irq_fired` остался от
poll-модели для диагностики и совместимости.

## Poll-провайдер PS/2

`mouse_ps2_poll()` вызывается из `mouse_api_poll()` и обязана заполнить
`mouse_delta_t` при каждом вызове (даже при тишине отдает последнее
состояние кнопок). Логика разбора:

- перед опросом кольца один раз зовется `drain_ptr` — страховка от
  застрявших байтов при неработающем IRQ12;
- bit3 первого байта пакета всегда 1: байт без него — потерянная граница
  пакета, выбрасывается (счетчик resync в `debug3`);
- биты 0xC0 первого байта — переполнение x/y, пакет битый;
- дельты — 9-битное дополнение до двух: знаковые биты 0x10 (X) и 0x20 (Y),
  у Y знак дополнительно инвертируется (PS/2 считает «вверх» плюсом, на
  экране плюс — вниз);
- кнопки — биты 0..2 первого байта (L, R, M), состояние хранится между
  пакетами;
- дельты накапливаются между вызовами poll — пакетов между опросами может
  прийти несколько, все складываются.

## Реестр провайдеров и единый курсор

Реестр (до `MAX_POINT_DEVICES 4` записей) позволяет нескольким устройствам
двигать один курсор: `register_device(name, type, priority, poll_fn, priv)`
отдает индекс слота, `unregister_device` снимает устройство (место для
будущей USB-HID мыши, тип `PTYPE_USB_HID` зарезервирован). `mouse_api_poll()`
суммирует дельты всех активных провайдеров, объединяет кнопки по OR
(кнопка нажата, если ее держит любое устройство), двигает курсор с клампом
к границам экрана из `boot_info` (по умолчанию 640x480) и стартует из
центра. Позиция хранится внутри драйвера; ядро и приложения только читают
ее через poll.

## API (mouse_driver_api_t)

| Функция | Кто вызывает | Поведение |
|---|---|---|
| `poll(mouse_state_t*)` | ядро: `schedule()` каждый тик, `SYS_MOUSE_GET`/`SYS_MOUSE_POLL` | опрос всех провайдеров, движение курсора, позиция + дельта с прошлого вызова |
| `set_pos(x, y)` | `SYS_MOUSE_SET_POS` | принудительная установка курсора с клампом |
| `get_device_info(idx, out)` | `lsdev` и отладка | имя, тип, число кнопок провайдера |
| `register_device(...)` | будущий USB-HID | добавить провайдера в реестр |
| `unregister_device(idx)` | будущий USB-HID | убрать провайдера |
| `malloc_ptr / free_ptr / yield_ptr` | внедряются ядром | heap и асинхронный сон |
| `irq_fired_ptr` | внедряется ядром | флаг `mouse_irq_fired` (диагностика) |
| `read_byte(out)` | внедряется ядром | забрать AUX-байт из кольца (0/-1); не пришвелован — poll не трогает порт |
| `drain_ptr` | внедряется ядром | разложить застрявшие в OBF байты (страховка при мертвом IRQ12) |

Поля `debug1..debug5` заполняются при загрузке: число устройств в реестре,
принятых пакетов, resync-событий, шаг детекта и последний байт на нем.
`debug6` ядро читает как биты состояния fallback-детекта, текущий драйвер
его не выставляет.

## Системные вызовы

| Номер | Имя | Контракт |
|---|---|---|
| 72 | `SYS_MOUSE_GET` | возвращает eax = x (или -1, если драйвер не загружен), ebx = y, ecx = кнопки |
| 73 | `SYS_MOUSE_POLL` | ebx = Ring-3 указатель на `mouse_state_t` → eax = 0/-1 |
| 74 | `SYS_MOUSE_SET_POS` | ebx = x, ecx = y → eax = 0/-1 |

Пользовательские обертки — `userspace/lib/mouse.c` (линкуется как
`u_mouse.o` / `u_mouse_elf.o`): `u_mouse_get`, `u_mouse_poll`,
`u_mouse_set_pos`, `u_mouse_yield` (для циклов ожидания событий). Проверочный
пример — `userspace/examples/mouse_test/mtest`: печатает координаты и кнопки,
выход любой клавишей.

## Интеграция с ядром

- Загружается **динамически** из `/adrv/` по конфигу
  `/config/boot/boot.cfg` (секции `[driver_1]...`, ключ `name`) через
  `load_additional_drivers()`; распознается по `DESCR_MOUSE_DRIVER`.
- После загрузки ядро внедряет указатели: `malloc_ptr`, `free_ptr`,
  `yield_ptr`, `irq_fired_ptr`, `read_byte`, `drain_ptr`.
- `schedule()` (`task.c`) дергает poll на каждом тике таймера (100 Гц) —
  курсор двигается и копит пакеты даже тогда, когда приложения не зовут
  `SYS_MOUSE_*`.
- На время загрузки дополнительных драйверов ядро маскирует IRQ1 и IRQ12
  (сохраняет IMR через `inb(0x21)/inb(0xA1)`, ставит биты 0x02/0x10 и
  возвращает маски после цикла): ответ контроллера на чтение CCB приходит
  как обычный байт с AUX=0, и без маски обработчик IRQ1 вычитал бы его как
  скан-код — детект иногда падал на шаге чтения CCB (наблюдалось на 86Box).
  Внутри цикла загрузки `return` нет, поэтому маски гарантированно
  снимаются.

## Сборка

```
gcc  -m32 -march=i386 -ffreestanding -fno-common -fno-stack-protector
     -fno-asynchronous-unwind-tables -fno-unwind-tables -fno-pie
     -c drivers/mouse/mouse.c -o bin/mouse_d.o
nasm -f elf32 drivers/mouse/mouse_start.asm -o bin/mouse_d_start.o
ld -m elf_i386 --no-warn-rwx-segments --emit-relocs -T drivers/userspace_driver.ld \
   bin/mouse_d_start.o bin/mouse_d.o bin/drv_ports_io.o bin/dlib.o \
   -o bin/mouse_driver.elf
```

Готовый `mouse_driver.elf` кладется на диск в каталог `/adrv/` под именем
`mouse.drv` (в FAT-образе — `::/ADRV/MOUSE.DRV`), имя включается в
`boot.cfg`.
