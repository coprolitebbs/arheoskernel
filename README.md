# Archeoskernel

**Archeoskernel** — экспериментальное ядро и загрузчик операционной системы x86.

Загрузчик написан на NASM Assembly.

Микроядро на C и NASM.

Проект создавался в академических целях для реализации низкоуровневой загрузки старого железа архитектуры x86: работы BIOS, файловой системы EXT2, VBE-графики, защищённого режима процессора и передачи управления микроядру и исполнения задач ядра.

## Возможности

На текущем этапе загрузчик может:

- Загружаться через BIOS (Legacy BIOS boot)
- Работать с HDD-образом через INT 13h Extensions (LBA)
- Читать файловую систему EXT2 или FAT12
- Находить и загружать kernel по inode
- Работать с блоками EXT2 inode
- Загружать ядро размером до ~1 МБ
- Загружать основные драйверы фреймбуфера и работы с ФС
- Формировать структуру bootinfo для передачи ядру
- Включать линию A20
- Инициализировать VBE видеорежим 1024х768
- Настраивать GDT
- Переключаться в Protected Mode (x86 32-bit)
- Передавать управление ядру



Что сделано по ядру на текущий момент:

- GDT/IDT;
- поддержка TSS;
- Консольный framebuffer для вывода текста
- вывод пикселей;
- консольный растровый шрифт CP866 8×8;
- вывод строк и отладочной информации непосредственно на экран.
- физический менеджер памяти (PMM);
- виртуальная память (VMM);
- страничная адресация;
- отдельные адресные пространства процессов.
- Прерывания
- обработчики исключений CPU;
- обработчики аппаратных IRQ;
- программные системные вызовы;
- корректное сохранение и восстановление контекста процессора.
- переход Ring0 → Ring3;
- пользовательские процессы;
- отдельный пользовательский стек;
- вытесняющее переключение задач и переключение по таймерному IRQ;
- очистка завершённых задач.

## Архитектура

Схема загрузки:


- BIOS -> bootloader (stage1) -> stage2 (драйвер EXT2 или FAT12, Загрузка ядра, Инициализация VBE, Включение A20, установка GDT, Защищенный режим, Передача управления ядру)

---

## Этапы загрузки

### Stage 1

Первый загрузочный сектор:

- находится в MBR
- выполняется BIOS
- загружает второй этап загрузчика

Stage1 выполняет только минимальную работу:

- настройка окружения
- поиск stage2
- передача управления

bootloader представлен в трех вариантах: 

- boot_720.asm (output/fat12_720.img) - загрузчик для дискет 5.25 720Кб
- boot_1440.asm (output/fat12_1440.img) - загрузчик для дискет 3.5 1.44Мб
- boot_hdd.asm (output/hdd_ext2.img) - загрузчик для диска IDE с файловой системой EXT2


---

### Stage 2

Основная логика загрузчика:

- работа с диском
- чтение c файловой системы EXT2 или FAT12
- загрузка ядра
- загрузка драйвера фреймбуфера fb_dr.drv
- загрузка драйвера файловых систем FAT12 и EXT2 fs_dr.drv
- заполнение структуры bootinfo 
- переход в protected mode
- передача управления ядру

stage2-loader представлен в двух вариантах:

- f12ld.asm - загрузчик ядра с файловой системы FAT12 дискеты
- hddld.asm - загрузчик ядра с файловой системы EXT2 жесткого диска

---

### Stage 3

Основное ядро:

На текущий момент запускает два пользовательских процесса, выводит отладочную информацию на экране.

Поскольку ядро не закончено, не ждите чего-то более внятного пока что.

## Kernel

Ядро собирается общим скриптом build.sh и укладывается в образ диска и дискет в каталог /output/

./output/fat12_720.img - образ дискеты 5.25 720Кб
./output/fat12_1440.img - образ дискеты 3.5 1.4Мб
./output/hdd_ext2.img - образ диска с файловой системой EXT2



---

## Передача управления ядру

После загрузки:

1. Ядро находится в памяти
2. Включается Protected Mode
3. Загружаются сегменты GDT
4. Управление передается:

```
jmp 0x08:0x100000
```


Перед запуском ядру через регистры процессора передаются параметры:

- EDI = framebuffer address

- ESI = framebuffer pitch

- EDX = bytes per pixel

## Сборка

Сборка происходит автоматически с помощью скрипта build.sh

Требуется:

- nasm
- qemu
- dosfstools
- genext2fs
- e2fsprogs

Сборка проверялась на Mac Os, все пакеты можно установить через brew install


Запуск

Пример запуска через QEMU:

- Запуск с образа дискеты:

```
qemu-system-i386 -drive file=output/fat12_720.img,format=raw,if=floppy -vga std -display cocoa -debugcon stdio -global isa-debugcon.iobase=0xe9
```

- Запуск с образа hdd:

```
qemu-system-i386 -drive file=output/hdd_ext2.img,format=raw,if=ide -vga std -display cocoa -debugcon stdio -global isa-debugcon.iobase=0xe9
```
