# Archeoskernel

**Archeoskernel** — экспериментальное ядро и загрузчик операционной системы для архитектуры x86.

Загрузчик написан на NASM Assembly.

Микроядро на C и NASM.

Проект создавался в академических целях для реализации низкоуровневой загрузки старого железа архитектуры x86: работы c прерываниями BIOS, файловой системы EXT2, VBE-графики, защищённого режима процессора, передачи управления микроядру и исполнения задач ядра.

## Возможности

На текущем этапе загрузчик состоит из двух частей - stage1 и stage2.

Загрузчик stage1 представляет из себя два варианта - загрузчик для файловой системы FAT12 ([boot_720.asm](boot_720.asm) и [boot_1140.asm](boot_1140.asm))и загрузчик для файловой системы EXT2 ([boot_hdd.asm](boot_hdd.asm)).

Загрузчик stage2 представляет из себя так же два варианта - загрузчик общий для дискет fat12 [f12ld.asm](f12ld.asm) и загрузчик для дисков с файловой системой EXT2 [hddld.asm](hddld.asm). 


Загрузчик может:

- Загружаться через BIOS (Legacy BIOS boot)
- Работать с HDD или дискетой в файловой системе FAT12 через INT 13h Extensions (LBA)
- Читать файловую систему EXT2 или FAT12
- Находить и загружать файл ядра kernel в верхнюю память 
- Работать с блоками EXT2 inode или c кластерами FAT12
- Загружать основные драйверы фреймбуфера и работы с ФС
- Формировать структуру bootinfo для передачи ядру
- Включать линию A20
- Инициализировать VBE видеорежим 1024х768
- Настраивать GDT
- Переключаться в Protected Mode (x86 32-bit)
- Передавать управление ядру



Что сделано по ядру на текущий момент:

- GDT/IDT;
- поддержка TSS;
- Консольный framebuffer для вывода текста и вывода пикселей;
- консольный растровый шрифт CP866 8×8;
- вывод строк и отладочной информации непосредственно на экран;
- физический менеджер памяти (PMM);
- виртуальная память (VMM) и менеджер страниц для нее;
- страничная адресация;
- отдельные адресные пространства процессов;
- Прерывания;
- обработчики исключений CPU;
- обработчики аппаратных IRQ;
- программные системные вызовы для пользовательских процессов;
- пользовательские процессы (пока существуют как образы в памяти, не загружаясь с диска) и отдельный пользовательский стек для каждого;
- вытесняющее переключение задач и переключение по таймерному IRQ;
- очистка завершённых задач и страниц памяти под них;
- Поддержка отдельных драйверов файловых систем, вызов их функций через API для работы в адресном пространстве ядра;
- Поддержка общей виртуальной файловой системы в ядре, с возможностью монтирования отдельных файловых систем в отдельные каталоги;
- Загрузка драйверов с файловой системы через VFS
- Загрузка пользовательских программ типа "Flat binary" с файловой системы через VFS
- Поддержка библиотек типичных функций работы с ядром для пользовательских программ 
- Поддержка стандартных потоков STDIN, STDOUT, STDERR для пользовательских программ
- Поддержка конфигурационных файлов задающих параметры инициализации ядра. Основной конфиг находится в [/config/boot/boot.cfg](userspace/filesystem/config/boot/boot.cfg). При сборке все файлы, не являющиеся исполняемыми, в том числе, конфигурационные, - копируются в образ из директории ./userspace/filesystem данного проекта
- Поддержка UTF-8, локалей пользователя и переключение между ними по сочетанию клавиш, которое настраивается в [/config/boot/boot.cfg](userspace/filesystem/config/boot/boot.cfg). Шрифт встроенный пока один и содержит глифы en/ru. Подключены две раскладки по дефолту - EN и RU, переключение между локалями настроено через сочетание CTRL+SHIFT. Для маппинга глифов символов в шрифте применительно к локали существует файл описания маппинга. Оба файла для текущих раскладок берутся из /config/locales/ (или [./userspace/filesystem/config/locales/](userspace/filesystem/config/locales) проекта)

## Архитектура

Схема загрузки:


- BIOS -> bootloader (stage1) -> stage2 (драйвер EXT2 или FAT12, Инициализация VBE, Включение A20, Загрузка с диска в память трех основных драйверов: фреймбуффера, FAT12 и EXT2, Загрузка ядра, установка GDT, Защищенный режим, Передача управления ядру)
Далее ядро получает через структуру bootinfo параметры из загрузчика (разрешение и адрес фреймбуфера, если удалось инициализировать линейный фреймбуффер), 
ядро инициализирует GDT (снова, под новые параметры) и TSS менеджеры памяти (PMM, VMM), 
Далее, ядро производит точное определение фреймбуфера: Если загрузчик путем определения VBE установил, что у видеоадаптера имеется линейный фреймбуфер, то, ядро просто маркирует память фреймбуфера для использования. Если же линейного фреймбуфера нет (например, очень старая видеокарта), сначала производится поиск через PCI-шину видеокарты S3 Trio64 (специальные требования) и переключение ее в режим линейного фреймбуфера и получение его адреса, либо, если видеокарта не найдена, предполагается, что видеокарта встроенная, и под фреймбуфер отведен самый верхний участок памяти, по умолчанию, в 4Мб (Настраивается при компиляции ядра). Далее, так же происходит маркировка памяти фреймбуффера для отрисовки. 
Далее, ядро из памяти извлекает основные драйвера (фреймбуфера и файловых систем), перегружает их в память с релоцированием адресов секций, инициализирует драйвера, получая структуры API для работы с ними. 
Далее инициализируется общая файловая система VFS - текущий носитель, с которого была произведена загрузка, монтируется в /.
Далее загружаются дополнительные драйвера с каталога /adrv.
Далее запускается виртуальный терминал и командный процессор sekhmet.bin.

## Этапы загрузки

### Stage 1

Первый загрузочный сектор:

- находится в MBR
- выполняется BIOS
- загружает второй этап загрузчика

Stage1 выполняет только минимальную работу:

- настройка окружения
- поиск stage2
- передача управления

bootloader представлен в трех вариантах: 

- boot_720.asm (output/fat12_720.img) - загрузчик для дискет 5.25 720Кб
- boot_1440.asm (output/fat12_1440.img) - загрузчик для дискет 3.5 1.44Мб
- boot_hdd.asm (output/hdd_ext2.img) - загрузчик для диска IDE с файловой системой EXT2


---

### Stage 2

Основная логика загрузчика:

- работа с диском;
- чтение c файловой системы EXT2 или FAT12;
- загрузка ядра;
- загрузка c с диска драйвера фреймбуфера fb_dr.drv (файл fb_dr.drv);
- загрузка c с диска драйверов файловых систем FAT12 и EXT2 (f12_dr.drv и ext2_dr.drv);
- заполнение структуры bootinfo;
- переход в protected mode;
- передача управления ядру.

stage2-loader представлен в двух вариантах:

- f12ld.asm - загрузчик ядра с файловой системы FAT12 дискеты;
- hddld.asm - загрузчик ядра с файловой системы EXT2 жесткого диска.

---

### Stage 3

Основное ядро:

На текущий момент запускает терминал и командный процессор в нём, выводит информацию на экране, принимает ввод с клавиатуры.
Работает простое перенаправление вывода в файл через ">" по аналогии с DOS/Linux

Поскольку ОС не закончена, не ждите чего-то более внятного пока что.

## Kernel

Ядро собирается общим скриптом build.sh и укладывается в образ диска и дискет в каталог /output/

./output/fat12_720.img - образ дискеты 5.25 720Кб
./output/fat12_1440.img - образ дискеты 3.5 1.4Мб
./output/hdd_ext2.img - образ диска с файловой системой EXT2

## Передача управления ядру

После загрузки:

1. Ядро находится в памяти
2. Включается Protected Mode
3. Загружаются сегменты GDT
4. Управление передается:

```
jmp 0x08:0x100000
```


Перед запуском ядру через регистры процессора передаются параметры:

- EDI = framebuffer address

- ESI = framebuffer pitch

- EDX = bytes per pixel

## Сборка

Сборка происходит автоматически с помощью скрипта build.sh

Требуется:

- nasm
- qemu
- dosfstools
- e2tools
- e2fsprogs

Сборка проверялась на Mac Os, все пакеты можно установить через brew install


## Запуск

!В данном репозитории образ диска ext2 находится в ./output/ в запакованном виде

Пример запуска через QEMU:

- Запуск с образа дискеты:

```
qemu-system-i386 -drive file=output/fat12_720.img,format=raw,if=floppy -vga std -display cocoa -debugcon stdio -global isa-debugcon.iobase=0xe9
```

- Запуск с образа hdd:

```
qemu-system-i386 -drive file=output/hdd_ext2.img,format=raw,if=ide -vga std -display cocoa -debugcon stdio -global isa-debugcon.iobase=0xe9
```
