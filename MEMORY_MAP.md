# ARHeOS — карта используемой памяти

Карта составлена по исходникам репозитория `coprolitebbs/arheoskernel` (коммит `91bb3d8`).
Базовый сценарий — загрузка с дискеты **1.44 МБ** (`boot_1440.asm` → `f12ld.asm`); для 720 КБ
карта идентична (отличается только размер буферов FAT/кластера, отмечено в таблицах).
Отличия пути HDD (`boot_hdd.asm` → `hddld.asm`) сведены в §9.

Фазы загрузки:

- **RM-1** — stage1, boot-сектор (реальный режим, BIOS)
- **RM-2** — stage2, загрузчик ядра (реальный режим, A20 + unreal mode)
- **PM** — переход в защищённый режим внутри stage2
- **K** — ядро (32-бит, `kernel.c`, после `jmp 0x08:0x100000`, paging включается в `vmm_init`)

## 2. Области памяти по фазам

### Фаза RM-1: stage1 (`boot_1440.asm`, `boot_720.asm` — дискета; `boot_hdd.asm` — HDD)

| Диапазон | Размер | Область | Комментарий |
|---|---|---|---|
| `0x00007C00–0x00007DFF` | 512 Б | boot-сектор (stage1) | BIOS грузит с сектора 0 (HDD: LBA 0 = MBR); `ORG 0x7C00`, `DS=ES=SS=0` |
| `0x00007BFF` и ниже | до `0x500` | стек stage1 | `SS:SP = 0:0x7C00`, растёт вниз |
| `0x00080000–0x00081BFF` | 7168 Б | буфер корневого каталога | чтение через `int 13h`, сегмент `0x8000` |
| `0x00090000–0x000911FF` | 4608 Б | буфер FAT | сегмент `0x9000`; 1.44M: 9 секторов, 720K: 3 сектора (до `0x905FF`) |
| `0x00007E00–0x0000FBFF` | 32256 Б | stage2 (F12.LD) | 63 сектора; `jmp 0x0000:0x7E00` |

Данные stage1 (`drive`, `filename "F12     LD "`, `cluster`, `sector`, `root_start`…) лежат
внутри boot-сектора. У `boot_hdd.asm` вместо BPB — таблица разделов MBR (один раздел
`0x83` с LBA 1), stage2 читается с LBA 1 теми же 63 секторами в `0x7E00`.

### Фаза RM-2: stage2 (`f12ld.asm` + `include/*.inc`)

| Диапазон | Размер | Область | Комментарий |
|---|---|---|---|
| `0x00007E00–0x0000FBFF` | 32256 Б | образ stage2 | код, данные, `gdt_start/gdtr` (3 дескриптора: null, `0x08` code flat, `0x10` data flat), буферы `vbe_ctrl_info` (512 Б) и `mode_info` (256 Б); в конце маркер целостности `"S2*63*"` |
| `0x0000FC00–0x0000FFF0` | ~1 КБ | стек stage2 (RM) | `SS:SP = 0:0xFFF0`, растёт вниз |
| `0x00000600–0x000007FF` | 512 Б | копия boot-сектора | `bpb_init` читает LBA 0 в `0:0x0600`; там же media byte для верификации FAT (`cs:0x0615`) |
| `0x00005000–0x0000580B` | ~2 КБ | bootinfo-блок | см. §6 |
| `0x00006000–…` | N×24+2 Б | таблица E820 | счётчик в `0x6000`, записи с `0x6002` (`int 15h`, AX=E820) |
| `0x00020000–0x00020200` | 512 Б–1 КБ | `KERNEL_SEG 0x2000` | staging-буфер кластера ядра перед копированием выше 1 МБ |
| `0x00030000–…` | дин. | модули `.DRV` | старт `module_next_segment = 0x3000`; шаг `ceil(size/16)+16` параграфов (+256 Б); проверка потолка `0x9C000` |
| `0x00080000–0x00081BFF` | 7168 Б | корень FAT12 | перечитывается при поиске KERNEL (`fat12_find_file`) уже после загрузки драйверов |
| `0x00090000–0x000911FF` | 4.5 КБ | FAT12 | используется `fat12_next_cluster` при загрузке ядра |
| выше `0x100000` | = размеру KERNEL | ядро | `fat12_load_kernel_high`: unreal mode (`GS` с лимитом 4 ГБ), побайтовое копирование из `0x20000` в `0x100000` |

### Фаза PM: финал stage2 (`pm_entry`)

| Регистр/область | Значение | Комментарий |
|---|---|---|
| `GDTR` | база внутри образа stage2 (`0x7E00…0xFBFF`) | адрес корректируется сложением `0x7E00`, если линкер дал смещение |
| `SS:ESP` | `0x10:0x00090000` | стек PM, растёт вниз в зону ниже 0x90000 |
| `EBX` | `0x00005000` | указатель `boot_info` для ядра |
| `CS:EIP` | `0x08:0x00100000` | вход в ядро |

### Фаза K: ядро (`kernel.c`, `kernel.ld`)

| Диапазон | Размер | Область | Комментарий |
|---|---|---|---|
| `0x00100000…` | до `_kernel_end` | образ ядра | binary-линк: `.text` (kernel.o первым — `_start` точно на `0x100000`) → `.rodata` (в т.ч. эталон `vbe_rm_blob`) → `.data` → `.bss` (`_bss_start…_bss_end` обнуляется в `_start`) |
| внутри `.bss` | 1040 Б | `gdt[130]` | GDT ядра перестраивается `gdt_init()` |
| внутри `.bss` | 2 КБ | `idt[256]` | IDT ядра (`idt_init()`) |
| внутри `.bss` | 4 КБ | `idle_stack[1024]` | стек idle-задачи |
| `0x00004000–0x000044FF` | ~1.25 КБ | VBE RM-тримплин | `vbe_rm_init()` копирует блоб из `.rodata`; вызов из PM: `lcall $0x08,$0x4000` |
| `0x00070000–0x000701FF` | 512 Б | ISA DMA-буфер FAT12 | `FAT12_DMA_BUFFER 0x00070000`, канал 2 (`fat12_dma.h`) |
| `0x00005000/5100/5200/5400` | — | bootinfo | `bootinfo_init()` читает; `boot_info->framebuffer` обновляется |
| `0x00006000/0x00006002` | — | E820 | `pmm_init()` берёт карту отсюда |
| `0x00090000` | — | `STACK_ADDRESS` | верх стека PM/TSS `esp0` до `init_tasking`, растёт вниз; стеки задач — по 4 страницы (16 КБ) из PMM |
| после `_kernel_end` | ≈RAM/8/4K | bitmap PMM | `bitmap = _kernel_end` (align 4K), за ним `mem_ptr` — начало выдачи страниц |
| `0x00C00000–0x00FFFFFF` | 4 МБ | зона драйверов ELF | `driver_elf.c`: `DRIVER_LOAD_ADDR = 0xC00000`, последовательная загрузка до `0x1000000` |

Резервы PMM (`pmm_init`): `0–0xFFFF` (IVT/BDA/тримплин), `0xA0000–0xFFFFF` (VGA/BIOS/EBDA),
`0x100000–mem_ptr` (ядро+bitmap), `0xC00000–0xFFFFFF` (драйверы), страницы LFB; всё ниже 1 МБ
вообще не выдаётся, PCI hole отрезается по `PCI_HOLE_START = 0xC0000000`.

## 3. Путь «диск → ОЗУ» (1.44M дискета)

| Что | На диске | В ОЗУ |
|---|---|---|
| stage1 (`boot_1440.bin`) | сектор 0 (перезаписывает BPB-сектор mkfs.fat) | `0x7C00`, 512 Б |
| stage2 (`F12.LD`) | кластеры файла | `0x7E00`, ровно 63 сектора (32256 Б) |
| FAT | секторы 1–9 | `0x90000` |
| корневой каталог | секторы 19–32 | `0x80000` |
| драйверы (5 файлов `.DRV`) | кластеры FAT12 | `0x30000` + динамически, шаг `ceil(size/16)+16` параграфов |
| ядро (`KERNEL`) | кластеры FAT12 | staging `0x20000` → `0x100000` (unreal mode) |
| карта памяти | `int 15h` AX=E820 | `0x6002` (счётчик `0x6000`) |
| метаданные | — | `0x5000`–`0x580B` (см. §6) |

Порядок в `f12ld.asm`: BPB → A20 → FAT → корень → драйверы 0–4 → E820 → поиск/загрузка
KERNEL → `vbe_init` (таблица режимов в `0x5400`) → bootinfo → GDT/`CR0.PE` → `jmp 0x08:0x100000`.

## 4. Драйверы (`drivers/`)

Два жизненных цикла в памяти:

1. **RM-2, blobs.** Stage2 грузит ELF-файлы как есть: `FB_DR.DRV` → `BLOCK.DRV` → `USB.DRV`
   → `F12_DR.DRV` → `EXT2_DR.DRV` с сегмента `0x3000` (физ. `0x30000`), после каждого — 256 Б
   padding. Сегменты и размеры сохраняются в `module_info[5]` (`0x5200`).
   Дополнительные драйверы лежат на диске в `/ADRV` (`KBDPS2.DRV`, `VESA.DRV`) и грузятся ядром позже.
2. **K, ELF-перенос.** `driver_elf.c` парсит ELF-образы (линкер `drivers/userspace_driver.ld`,
   база 0) и раскладывает секции последовательно с `DRIVER_LOAD_ADDR = 0xC00000`
   до `0x1000000` — зона зарезервирована в PMM.

Драйвер | Файл | Аппаратура в памяти/портах
---|---|---
`fb_driver` | `FB_DR.DRV` | пишет в LFB из bootinfo; курсор CRT `0x3D4/0x3D5`
`vesa_fb` | `ADRV/VESA.DRV` | LFB + смена режима через VBE RM-тримплин (`0x4000`)
`kbd_driver` | `ADRV/KBDPS2.DRV` | порты `0x60/0x64`
`fat12_driver` | `F12_DR.DRV` | FDC `0x3F0–0x3F7`, ISA DMA кан. 2 (`0x00–0x0F`, страница `0x81`), буфер DMA `0x70000`
`ext2_driver` | `EXT2_DR.DRV` | через block driver
`block_driver` | `BLOCK.DRV` | ATA primary `0x1F0–0x1F7` (+`0x3F6`)
`usb_driver` | `USB.DRV` | PCI `0xCF8/0xCFC`, UHCI/EHCI MMIO по BAR

## 6. Структуры обмена loader → kernel (`include/bootinfo.inc`)

| Адрес | Структура | Размер | Содержимое |
|---|---|---|---|
| `0x5000` | `boot_info` | 84 Б | magic `IBOO`, версия, LFB/pitch/w/h/bpp, флаги, `e820 → 0x6002`, `fs → 0x5100`, `modules → 0x5200` (5 шт.), VBE-таблица `→ 0x5400`, drive |
| `0x5100` | `filesystem_info` | 56 Б | тип ФС, геометрия FAT12/EXT2 |
| `0x5200` | `module_info[5]` | 5×44 Б | `start = сегмент<<4`, `size`, `type`, имя |
| `0x5400` | VBE-таблица режимов | 12+64×16 Б | шапка `VBSM` + записи режимов (mode, x, y, bpp, pitch, PhysBase) |

Адрес `boot_info` передаётся ядру в `EBX` и используется как есть (`BOOTINFO_ADDR equ 0x5000`).

## 9. Отличия HDD-пути (`boot_hdd.asm` → `hddld.asm`)

- stage1 — MBR с таблицей разделов (раздел от LBA 1), без BPB; LBA через `int 13h` AH=41h/42h с фолбэком на CHS.
- stage2 (`hddld.asm`, те же 63 сектора в `0x7E00`) читает EXT2; вместо буферов FAT/корня
  использует свои блоки в свободной зоне `0x10000–0x1FFFF`:
  суперблок `0x10000` (`SUPER_SEG`), дескрипторы групп `0x12000` (`GDT_SEG`), таблица inode
  `0x14000` (`INODE_SEG`), блок каталога `0x16000` (`DIR_SEG`), косвенные блоки `0x18000` (`INDIRECT_SEG`).
- Staging ядра тот же — `0x20000` (блоки по 1 КБ), перенос в `0x100000` — тот же unreal mode.
- PM-переход, E820 (`0x6000`), bootinfo (`0x5000`), драйверы (с `0x30000`), стек PM (`0x90000`)
  и ядро — идентично дискетному пути.

## 10. Замечания (риски)

1. **Стек PM на `0x90000`.** Он растёт вниз, а код stage2 разрешает драйверам занимать до
   `0x9C000` — при суммарном размере модулей больше ~384 КБ стек затрёт их. Фактически
   драйверы должны кончаться и ниже `0x80000`: после их загрузки stage2 снова использует
   буфер корня (`0x80000`, `fat12_find_file`) и FAT (`0x90000`, `fat12_next_cluster`).
2. **Стек stage2 в RM — ~1 КБ** (`SP=0xFFF0` при верхе образа `0xFBFF`); запас на BIOS-вызовы
   и `fdc_pio` минимален.
3. **`BOOT_LOADER_NAME` в boot_info** записан как 16-битный офсет внутрь stage2 — валиден,
   пока stage2 жив в `0:0x7E00`; при переиспользовании этой памяти ядром указатель повиснет.
